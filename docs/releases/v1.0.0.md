# AcerFALDv2 v1.0.0

First tracked release of **FaldSync / AcerFALDv2** — a clean-room Windows utility that keeps an
Acer Mini-LED monitor's local dimming engaged while HDR is on, keeps brightness and contrast
controllable in HDR, lowers the Windows SDR white level, and optionally applies a reversible
gamma 2.2 correction to SDR content inside the HDR container.

Repository version **1.0.0**. Shipped components:

| Component | Version | Notes |
| --- | --- | --- |
| AcerFALDv2 (portable) | 2.2.0 | self-contained single-file exe, no .NET required |
| FaldSync UI (tray) | 1.3.0 | framework-dependent build, needs .NET 8 |
| FaldSync engine | source | console CLI and shared DDC/HDR engine |

Tested on the Acer Nitro **XV275K P5** (4K 160 Hz, Mini-LED FALD, DisplayHDR 1000).

## Highlights

- **HDR + FALD automation** — forced User → HDR transition, settle and verification,
  brightness/contrast control while HDR is on, and restore to the SDR User preset.
- **Comfortable SDR on a bright panel** — Windows SDR content white from 80 to 480 nits in
  4-nit steps, plus an optional, reversible gamma 2.2 scanout correction.
- **Dark-first tray UI** — light/dark switch, debounced sliders, HDR and gamma toggles,
  re-apply/restore actions, minimize-to-tray and saved settings.
- **Monitor volume and input** — speaker volume over VCP `0x62`; DP, HDMI 1, HDMI 2 and DP ALT
  over VCP `0x60`.
- **App-managed auto-switch** — re-selects the chosen input after startup or wake only when the
  panel reports a different one. The monitor's own Auto Source stays OSD-only.
- **Portable build** — `AcerFALDv2.exe` carries its own runtime, has its own mutex, tray identity,
  config and log, and needs no .NET installation.

## Fixed in this release

- **OSD/DDC sync.** Brightness, contrast, volume and input changed with the monitor's own
  joystick are now read back every 2.5 s; the sliders and active input follow the panel instead
  of silently drifting.
- **Stale DDC handle after an input change.** Windows re-enumerates the display and invalidates
  the physical-monitor handle, which used to leave every later read/write failing until an app
  restart. The app now pings the panel, re-acquires the handle, retries the operation, refuses to
  bind to an unrelated display, and recovers automatically. The input buttons stay usable while
  the panel is away and the tray has a manual **Reconnect to monitor** action. The console
  watcher recovers the same way.

## Download and install

Download `AcerFALDv2-portable.zip` from the **Assets** section of this release.

1. Extract the zip to a folder you can write to.
2. Run `AcerFALDv2.exe`.
3. Optional: put a shortcut in `shell:startup` to start it at login.

Settings and the log live next to the exe (`faldsync.json`, `faldsync.log`). The exe is unsigned,
so Windows SmartScreen may report "Unknown publisher"; choose **More info → Run anyway** if you
trust the build.

## Requirements

- Windows 10 or 11, x64.
- A monitor with DDC/CI (MCCS) enabled in its OSD.
- For source builds only: the .NET 8 SDK. The portable release needs no runtime.

## Known limits

- Local dimming on this panel needs **an HDR signal and the monitor's HDR display mode**. True
  SDR-signal FALD is not available on the current firmware.
- While the panel is showing another input, DDC/CI over this PC's cable may stop answering
  completely. No software can force the switch back in that state; use the monitor joystick. The
  app reconnects automatically when the panel returns.
- FALD zone-response speed is fixed by P5 firmware. There is no Adaptive Dimming DDC control.
- The gamma correction uses the AMD `SetDeviceGammaRamp` curve; an NVIDIA-specific path is not
  implemented.
- Live input switching is not exercised in automated tests because it would drop this PC's
  DisplayPort signal.
